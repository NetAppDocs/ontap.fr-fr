= Combinaisons prises en charge d'opérations sur les fichiers et de filtres que ONTAP FPolicy surveille pour S3
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Lorsque vous configurez votre événement FPolicy, vous devez savoir que seules certaines combinaisons d'opérations sur les fichiers et de filtres sont prises en charge pour la surveillance des opérations d'accès aux objets S3.

À partir d'ONTAP 9.20.1, FPolicy prend en charge les notifications d'événements d'objets S3 sur les compartiments NAS. FPolicy S3 fonctionne uniquement en mode asynchrone et non obligatoire.

Le tableau suivant présente la liste des opérations sur les fichiers et des combinaisons de filtres prises en charge pour la surveillance FPolicy des événements d'accès aux objets S3 :

|===

 a| 
object_create
 a| 
object-create-with-put, object-create-with-copy, object-create-with-complete-mpu



 a| 
suppression d'objet
 a| 
exclude-multi-delete



 a| 
object_tag
 a| 
object-tag-put, object-tag-delete

|===


[[filter-descriptions]]
== Descriptions des filtres

La liste suivante décrit chaque filtre FPolicy S3 :

* object-create-with-put: Surveiller les opérations de création d’objets effectuées à l’aide d’une requête PUT.
* object-create-with-copy: Surveiller les opérations de création d’objets effectuées à l’aide d’une requête COPY.
* object-create-with-complete-mpu: Surveiller les opérations de création d’objets effectuées lors de la finalisation d’un téléchargement multipart.
* exclude-multi-delete: Exclure les notifications pour les objets supprimés dans le cadre d’une requête de suppression multiple. Lorsque ce filtre est défini, FPolicy génère des notifications uniquement pour les opérations de suppression d’objet unique.
* object-tag-put: Surveiller les opérations qui ajoutent ou modifient une balise d’objet.
* object-tag-delete: Surveillez les opérations qui suppriment une balise d’objet.




[[additional-considerations-for-s3-fpolicy-events]]
== Considérations supplémentaires pour les événements S3 FPolicy

* Seules les opérations S3 réussies, initiées par le client, génèrent des notifications FPolicy. Les opérations générées en interne (telles que l'expiration d'un objet ou la restauration d'un instantané) et les opérations ayant échoué ne génèrent pas de notifications.
* Les opérations GET (lecture) ne sont pas prises en charge pour la surveillance FPolicy de S3.
* Une requête de suppression multiple peut supprimer jusqu'à 1 000 objets. FPolicy génère une notification par objet supprimé avec succès. Chaque notification d'une même requête de suppression multiple partage le même identifiant de requête FPolicy et le même identifiant de requête S3 à des fins de corrélation.
* Les notifications d'accès refusé ne sont pas prises en charge pour les événements S3.
