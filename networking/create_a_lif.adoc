= Création des LIF ONTAP
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Une machine virtuelle de stockage (SVM) fournit des données aux clients via une ou plusieurs interfaces logiques (LIF), qui sont des adresses IP associées à un port physique ou logique. Vous devez créer des LIF sur les ports que vous souhaitez utiliser pour accéder aux données. En cas de défaillance d'un composant, une LIF peut basculer ou migrer vers un autre port physique afin de continuer à communiquer avec le réseau.

.Avant de commencer
* Vous devez être un administrateur de cluster pour effectuer cette tâche.
* Le port réseau physique ou logique sous-jacent doit être en état administratif `up`.


.Description de la tâche
Vous pouvez créer des LIF IPv4 et IPv6 sur le même port réseau.

.Création de LIFS avec des sous-réseaux
* NetApp recommande de créer des objets de sous-réseau pour toutes les LIF sur les SVM de données. Ceci est particulièrement important pour les configurations MetroCluster, où l'objet de sous-réseau permet à ONTAP de déterminer les cibles de basculement sur le cluster de destination, car chaque objet de sous-réseau possède un domaine de broadcast associé. Si vous prévoyez d'utiliser un nom de sous-réseau pour allouer l'adresse IP et la valeur du masque de réseau d'une LIF, le sous-réseau doit déjà exister. Pour obtenir des instructions, reportez-vous à link:../networking/create_a_subnet.html["Créez un sous-réseau"].
* Une LIF gérant le trafic intracluster entre des nœuds ne doit pas se trouver sur le même sous-réseau que le trafic de gestion d'une LIF ou encore le trafic de données géré par une LIF.
* Lorsque vous créez une interface réseau intercluster, vous ne pouvez pas spécifier une adresse IP qui se trouve dans la plage d'un sous-réseau existant.
* À partir d'ONTAP 9.7, lors de la création d'une interface réseau avec un sous-réseau, ONTAP sélectionne automatiquement une adresse IP disponible dans le sous-réseau sélectionné et l'attribue à l'interface réseau. Vous pouvez modifier le sous-réseau s'il en existe plusieurs, mais vous ne pouvez pas modifier l'adresse IP.


.Prise en charge de la fonctionnalité de création de LIF par version ONTAP
La prise en charge des fonctionnalités liées à la création de LIF varie selon la version d'ONTAP.

[cols="2"]
|===
| À partir de la version ONTAP | Fonction 


| 9.12.1 | Prise en charge de la création d'interfaces réseau pour les configurations NFS sur RDMA dans System Manager. Pour plus d'informations, consultez xref:../nfs-rdma/configure-lifs-task.html[Configuration DES LIF pour NFS sur RDMA]. 


| 9.11.1 | Prise en charge du basculement automatique des LIF iSCSI sur les systèmes All-Flash SAN Array (ASA). Pour une nouvelle LIF iSCSI, le basculement est automatiquement activé avec la stratégie  `sfo-partner-only` et le retour automatique défini sur  `true` si la SVM ne contient aucune LIF iSCSI existante ou si le basculement est activé sur toutes les LIF iSCSI existantes. Après la mise à niveau vers ONTAP 9.11.1 ou une version ultérieure, une nouvelle LIF iSCSI hérite de la stratégie de basculement  `disabled` si le basculement n'est pas activé sur les LIF iSCSI existantes dans la même SVM. En savoir plus sur link:../san-admin/asa-iscsi-lif-fo-task.html["Basculement de LIF iSCSI pour les plateformes ASA"] 


| 9.10.1 | Les `network interface` commandes incluent un `-rdma-protocols` paramètre pour les configurations NFS sur RDMA 


| 9.7 | Si d'autres LIF existent déjà pour la SVM dans le même sous-réseau, il n'est pas nécessaire de spécifier le port d'attache de la LIF. ONTAP choisit automatiquement un port aléatoire sur le nœud d'attache spécifié dans le même domaine de diffusion que les autres LIF déjà configurées dans le même sous-réseau. 


| 9.6  a| 
Les LIF utilisent des stratégies de service pour spécifier le type de trafic qu'elles gèrent. Les rôles sont utilisés pour spécifier le type de trafic dans ONTAP 9.5 et les versions antérieures.

.Restrictions de création de LIF
* Vous ne pouvez pas attribuer des protocoles NAS et SAN à la même LIF.
+
Cependant, les protocoles NAS et SAN basés sur Ethernet peuvent être présents sur le même port physique.

* Un trafic de gestion des LIF doit être configuré pour chaque SVM (Storage Virtual machine) prenant en charge les protocoles SAN.
* LIF NVMe
+
** Le protocole NVMe doit être pris en charge par l'adaptateur FC sur lequel la LIF est créée.
** Les LIFs et namespaces NVMe doivent être hébergés sur le même nœud.
** Un maximum de deux LIF NVMe traitant le trafic de données peut être configuré par SVM, par nœud.
** Une interface LIF de données ne peut pas être partagée entre NVMe et tout autre protocole. NVMe peut être le seul protocole sur les interfaces LIF de données NVMe.
+
En savoir plus sur link:../nvme/support-limitations.html["Configuration, prise en charge et limitations de NVMe"].



* LIF SMB
+
** Ne configurez pas les LIF qui transportent du trafic SMB pour qu'elles reviennent automatiquement à leurs nœuds d'origine si le serveur SMB héberge une solution pour des opérations sans interruption avec Hyper-V ou SQL Server sur SMB.




.Étapes
Utilisez System Manager ou l'interface de ligne de commande (CLI) pour créer une LIF.

[role="tabbed-block"]
====
.System Manager
--
.Avant de commencer
Si votre cluster comporte un grand nombre d'interfaces réseau logiques (LIF), vous pouvez vérifier la capacité LIF prise en charge sur le cluster avant d'en créer de nouvelles. À partir d'ONTAP 9.12.1, vous pouvez afficher le débit dans la grille Network Interface de System Manager.

. Sélectionnez *réseau > Présentation > interfaces réseau*.
. Sélectionnez image:icon_add.gif["Ajouter une icône"].
. Sélectionnez l'un des rôles d'interface suivants :
+
.. Les données
.. Intercluster
.. Gestion SVM


. Sélectionnez le protocole :
+
.. SMB/CIFS ET NFS
.. ISCSI
.. FC
.. NVMe/FC
.. NVMe/TCP


. Nommez la LIF ou acceptez le nom généré par vos sélections précédentes.
. Acceptez le nœud de départ ou utilisez le menu déroulant pour en sélectionner un.
. Si au moins un sous-réseau est configuré dans l'IPspace du SVM sélectionné, la liste déroulante sous-réseau est affichée.
+
.. Si vous sélectionnez un sous-réseau, choisissez-le dans la liste déroulante.
.. Si vous continuez sans sous-réseau, la liste déroulante broadcast domain s'affiche :
+
... Veuillez indiquer l'adresse IP. Si l'adresse IP est déjà utilisée, un message d'avertissement s'affiche.
... Spécifiez un masque de sous-réseau.




. Sélectionnez le port d'accueil dans le domaine de diffusion, soit automatiquement (recommandé), soit en sélectionnant un dans le menu déroulant. Le contrôle du port Home s'affiche en fonction du domaine de diffusion ou de la sélection du sous-réseau.
. Enregistrez l'interface réseau.


--
.CLI
--
. Si vous le souhaitez, définissez le niveau de privilège sur avancé pour afficher la capacité de l'interface réseau.
+
.. Définissez le niveau de privilège sur avancé :
+
[source, cli]
----
set -privilege advanced
----
.. Consultez la capacité LIF prise en charge par chaque nœud :
+
[source, cli]
----
network interface capacity details show
----
+
En savoir plus sur la  `network interface capacity details show`commandelink:https://docs.netapp.com/us-en/ontap-cli/search.html?q=network+interface+capacity+show["Référence de commande ONTAP"^].



. Déterminez les ports de broadcast domain que vous souhaitez utiliser pour le LIF.
+
[source, cli]
----
network port broadcast-domain show -ipspace _ipspace1_
----
+
....
IPspace     Broadcast                       Update
Name        Domain name   MTU   Port List   Status Details
ipspace1
            default       1500
                                node1:e0d   complete
                                node1:e0e   complete
                                node2:e0d   complete
                                node2:e0e   complete
....
+
Pour en savoir plus, `network port broadcast-domain show` consultez le link:https://docs.netapp.com/us-en/ontap-cli/network-port-broadcast-domain-show.html["Référence de commande ONTAP"^].

. Vérifiez que le sous-réseau que vous souhaitez utiliser pour les LIF contient suffisamment d'adresses IP inutilisées.
+
[source, cli]
----
network subnet show -ipspace _ipspace1_
----
+
Pour en savoir plus, `network subnet show` consultez le link:https://docs.netapp.com/us-en/ontap-cli/network-subnet-show.html["Référence de commande ONTAP"^].

. Créez une ou plusieurs LIF sur les ports que vous souhaitez utiliser pour accéder aux données.
+
[source, cli]
----
network interface create -vserver _SVM_name_ -lif _lif_name_ -service-policy _service_policy_name_ -home-node _node_name_ -home-port port_name {-address _IP_address_ - netmask _Netmask_value_ | -subnet-name _subnet_name_} -firewall- policy _policy_ -auto-revert {true|false}
----
+
** `-home-node` Est le nœud vers lequel la LIF renvoie lorsque `network interface revert` La commande est exécutée sur le LIF.
+
Vous pouvez également indiquer si la LIF doit revenir automatiquement au nœud home et au port home-port avec l'option -auto-revert.

+
Pour en savoir plus, `network interface revert` consultez le link:https://docs.netapp.com/us-en/ontap-cli/network-interface-revert.html["Référence de commande ONTAP"^].

** `-home-port` Est le port physique ou logique vers lequel la LIF renvoie lorsque `network interface revert` La commande est exécutée sur le LIF.
** Vous pouvez spécifier une adresse IP avec les options  `-address` et  `-netmask`, ou vous pouvez activer l'allocation à partir d'un sous-réseau avec l'option  `-subnet_name`.
** Lors de l'utilisation d'un sous-réseau pour fournir l'adresse IP et le masque de réseau, si le sous-réseau a été défini avec une passerelle, une route par défaut vers cette passerelle est ajoutée automatiquement au SVM lorsqu'une LIF est créée à l'aide de ce sous-réseau.
** Si vous attribuez des adresses IP manuellement (sans utiliser de sous-réseau), vous devrez peut-être configurer une route par défaut vers une passerelle si des clients ou des contrôleurs de domaine se trouvent sur un autre sous-réseau IP. Pour en savoir plus, `network route create` consultez le link:https://docs.netapp.com/us-en/ontap-cli/network-route-create.html["Référence de commande ONTAP"^].
** `-auto-revert` Vous permet de spécifier si une LIF de données est automatiquement rétablie sur le nœud de rattachement en cas de démarrage, de modifications du statut de la base de données de gestion ou lors de la connexion réseau. Le paramètre par défaut est `false`, mais vous pouvez le définir sur `true` selon les stratégies de gestion de réseau de votre environnement.
**  `-service-policy` Depuis ONTAP 9.5, vous pouvez attribuer une policy de service pour la LIF avec le `-service-policy` option.
Lorsqu'une politique de services est spécifiée pour une LIF, cette règle est utilisée pour construire un rôle par défaut, une politique de basculement et une liste de protocoles de données pour la LIF. Dans ONTAP 9.5, les stratégies de service sont prises en charge uniquement pour les services de pairs intercluster et BGP. Dans ONTAP 9.6, vous pouvez créer des stratégies de service pour plusieurs services de données et de gestion.
** `-data-protocol` Permet de créer une LIF qui prend en charge les protocoles FCP ou NVMe/FC. Cette option n'est pas requise lors de la création d'une LIF IP.

.Exemples
La commande suivante crée une LIF et spécifie les valeurs d'adresse IP et de masque réseau à l'aide de `-address` et `-netmask` paramètres :

+
....
network interface create -vserver vs1.example.com -lif datalif1 -service-policy default-data-files -home-node node-4 -home-port e1c -address 192.0.2.145 -netmask 255.255.255.0 -auto-revert true
....
+
La commande suivante crée une LIF et attribue des valeurs d'adresse IP et de masque réseau à partir du sous-réseau spécifié (nommé client1_sub) :

+
....
network interface create -vserver vs3.example.com -lif datalif3 -service-policy default-data-files -home-node node-3 -home-port e1c -subnet-name client1_sub - auto-revert true
....
+
La commande suivante crée une LIF NVMe/FC et spécifie le `nvme-fc` protocole de données :

+
....
network interface create -vserver vs1.example.com -lif datalif1 -data-protocol nvme-fc -home-node node-4 -home-port 1c -address 192.0.2.145 -netmask 255.255.255.0 -auto-revert true
....
